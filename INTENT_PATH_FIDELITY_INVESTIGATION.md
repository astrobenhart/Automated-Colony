# Intent Path Fidelity Investigation

## Executive Summary

Pathfinding is still producing valid walkable paths around water and obstacles.

The first architectural break occurs between Intent and Presentation execution:

Simulation consumes path nodes one tile at a time. Intent then exposes only the agent's current simulation position plus the remaining path. If simulation advances faster than Presentation can visually reach the same position, the already-consumed simulation waypoints are no longer present in the Intent path.

Presentation then starts a new visual segment from the stale rendered position directly to the current simulation position. That straight-line interpolation can cross water even though the simulation never stepped onto water.

The renderer is not the root cause. It faithfully draws the Presentation snapshot it receives.

## Simulation Path

Focused probe:

- World size: `7 x 5`
- Water barrier: `x = 2`, `y = 1..4`
- Open crossing: `(2, 0)`
- Start: `(0, 2)`
- Destination: `(4, 2)`

Simulation path generated by `find_path`:

```text
[(0, 1), (0, 0), (1, 0), (2, 0), (3, 0), (4, 0), (4, 1), (4, 2)]
```

Terrain along that path:

```text
(0, 1) grass
(0, 0) grass
(1, 0) grass
(2, 0) grass
(3, 0) grass
(4, 0) grass
(4, 1) grass
(4, 2) grass
```

Result:

Simulation pathfinding still avoids water. The full path goes around the barrier through the open crossing at `(2, 0)`.

## Intent Path

After seven simulation movement steps, the agent is at:

```text
(4, 1)
```

Remaining simulation path:

```text
[(4, 2)]
```

Movement Intent produced at that moment:

```text
((4, 1), (4, 2))
```

This Intent path is valid for the current simulation state, but it no longer contains the waypoints the simulation already consumed:

```text
(0, 1), (0, 0), (1, 0), (2, 0), (3, 0), (4, 0)
```

Result:

Intent preserves the remaining path, but not the already-consumed route between the stale rendered position and the current simulation position. That is the key fidelity loss.

## Presentation Path

Presentation state before catching up:

```text
render position: (0.0, 2.0)
simulation position: (4, 1)
intent path: ((4, 1), (4, 2))
presentation queue: ((4, 1), (4, 2))
```

Presentation first visual segment:

```text
from: (0.0, 2.0)
to:   (4.0, 1.0)
```

Sampled rendered segment:

```text
(0.0, 2.0) -> tile (0, 2) grass
(1.0, 1.75) -> tile (1, 1) grass
(2.0, 1.5) -> tile (2, 1) water
(2.2, 1.45) -> tile (2, 1) water
(2.4, 1.4) -> tile (2, 1) water
(2.6, 1.35) -> tile (2, 1) water
(2.8, 1.3) -> tile (2, 1) water
(3.0, 1.25) -> tile (3, 1) grass
(4.0, 1.0) -> tile (4, 1) grass
```

Result:

Presentation is interpolating between distant points rather than adjacent simulation waypoints.

## Rendered Motion

The renderer consumes `PresentationAgentSnapshot.render_x` and `render_y`.

In the failing case, those positions are already on the straight-line Presentation segment from `(0.0, 2.0)` to `(4.0, 1.0)`. The renderer does not appear to simplify the path or choose a different route. It simply draws the position supplied by Presentation.

Result:

Renderer is faithful to Presentation state. It is not the layer where path fidelity is first lost.

## Root Cause

The current Intent and Presentation contract is incomplete for asynchronous visual catch-up.

Specific contributing implementation details:

- `movement_intent_for(agent)` builds Intent from the agent's current simulation position plus `agent.current_path`.
- `agent.current_path` contains only unconsumed future path nodes.
- `_step_along_path(...)` pops consumed waypoints as simulation moves.
- `PresentationAgent.observe_movement_intent(...)` replaces the active visual movement queue whenever the Intent id changes.
- The Intent id includes the current position and remaining path, so it changes after each simulation step.
- Presentation starts the next motion segment from the current rendered position to the first waypoint in the new Intent path.

When Presentation is behind simulation, that first waypoint may be several simulation steps ahead. Presentation then draws a direct chord from the old rendered position to the new simulation position.

This chord can cross impassable terrain.

## Architectural Assessment

Simulation:

Pass. Simulation still generates paths that avoid water and other non-walkable terrain.

Intent:

Partial pass. Intent preserves the currently remaining simulation path, but it does not preserve the complete route Presentation must still visually perform when Presentation is behind simulation.

Presentation:

Fail for path fidelity. Presentation consumes every waypoint currently present in its queue, but the queue has already lost earlier waypoints. Presentation also restarts movement toward the new first Intent waypoint whenever Intent changes, even if the visual agent has not reached previous waypoints.

Renderer:

Pass. Renderer displays Presentation positions faithfully.

## Recommended Fix

Do not change pathfinding.

Recommended implementation direction:

1. Preserve consumed-but-unrendered movement waypoints inside Presentation when Intent changes.
2. When a new movement Intent arrives, merge it with the existing visual queue instead of replacing the queue outright.
3. Drop only waypoints that Presentation has actually reached, not merely waypoints simulation has consumed.
4. If reconciliation is required, snap only when the current visual queue is invalid or impossible, and treat that as an explicit recovery path rather than normal movement.

The important rule is:

```text
Presentation may interpolate between adjacent simulation waypoints, but must never alter or simplify the navigation path.
```

## Documentation Recommendations

Add the following rule permanently to `DESIGN.md`, `ROADMAP.md`, and the relevant Presentation Motion task notes:

```text
Presentation may smooth timing, easing and animation, but it may only interpolate between adjacent waypoints approved by simulation. Presentation must never simplify, shortcut or replace the navigation path.
```

Also clarify that Intent paths must be treated as incremental updates to a Presentation-owned visual route, not as full replacements whenever simulation advances.

## Evidence Summary

The first divergence is:

```text
Simulation Path
  valid full route around water

Intent Path
  only current simulation position plus remaining path

Presentation Path
  stale render position to current simulation position

Rendered Motion
  faithful drawing of the invalid Presentation chord
```

Therefore the bug belongs to the Intent-to-Presentation movement handoff, specifically visual route preservation and queue reconciliation.
